# PROJECT CONTEXT: HydraQ Alpha (PoC)

## 1. Назначение системы
HydraQ Alpha — это микросервисная MLOps/QMLOps платформа для моделирования и предсказания нелинейных хаотических процессов (аттрактор Лоренца) на базе квантовых резервуарных вычислений (Quantum Reservoir Computing, QRC).

## 2. Архитектурные границы
- **FastAPI Gateway:** Асинхронный шлюз. Занимается только валидацией (Pydantic v2), диспетчеризацией задач в очередь и проксированием WebSocket/Redis. Не производит вычислений, не держит в памяти тяжелые файлы.
- **Celery Worker:** Изолированный вычислительный процесс (`concurrency=1`, `acks_late=True`). Занимается квантовым моделированием и обучением считывающего слоя.
- **MinIO S3:** Объектное хранилище артефактов (датасеты, веса `.pth`, графики). Работает по паттерну Zero-RAM Upload через presigned URLs.
- **Redis 7:** In-memory кэш и Pub/Sub брокер для передачи потоковой телеметрии шагов обучения в WebSocket.
- **RabbitMQ:** Брокер очередей задач между FastAPI и Celery.
- **Квантовое ядро (`libs/quantum`):** PyTorch на комплексных числах (`torch.complex64`), тензорные гейты, аналитический Readout (`torch.linalg.solve`).

## 3. Технические стандарты
- **Среда:** Python 3.12+, пакетный менеджер `uv` (команды `pip install` и `poetry` запрещены).
- **Линтер/Форматтер:** `Ruff` (строгая типизация, Google-style docstrings).
- **FastAPI:** Использование строго менеджера контекста `lifespan` (события `on_event` запрещены).
- **Качество кода:** Никаких заглушек (`pass`, `# TODO`), моков или фиктивных вычислений. Только рабочий, протестированный продакшн-код.
